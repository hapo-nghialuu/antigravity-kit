# Investigation Scaling

Decide when the investigation should stay local and when it should expand.

## Stay Small When

- one issue surface is involved
- one evidence stream is enough
- one clear hypothesis exists
- the next check is obvious and cheap

## Scale Up When

- there are multiple evidence sources
- the issue spans multiple directories or owners
- the investigation has 3 or more meaningful steps
- parallel evidence gathering would reduce time without causing confusion
- coordination itself becomes part of the problem

## Scaling Modes

### Sequential mode
Use when clarity matters more than speed.

### Parallel evidence mode
Split by source, not by guess.
Each branch should answer a different evidence question.

### Coordinated task mode
Use task tracking when the investigation has dependency chains or multiple handoffs.

## Rules for Parallel Work

- avoid overlap between evidence branches
- define what each branch must return
- merge findings only after branch outputs are available
- do not parallelize if the issue is still poorly framed

## De-Scaling Rule

If coordination overhead exceeds insight gained, collapse back to a smaller loop.

## Exit Condition

Choose the smallest mode that can still produce a trustworthy conclusion.
