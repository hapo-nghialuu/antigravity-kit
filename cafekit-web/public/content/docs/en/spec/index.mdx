# Spec Workflows

CafeKit Spec provides 6 workflow commands for **Spec-Driven Development (SDD)** - a software development methodology based on clear specifications before writing code.

## SDD Process

```text
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  spec-init  │───▶│ requirements│───▶│   design    │
│ (Initialize)│    │(Requirements)│   │   (Design)  │
└─────────────┘    └─────────────┘    └─────────────┘
                                              │
                       ┌─────────────┐       │
                       │  spec-impl  │◀──────┘
                       │(Implement)  │◀────┐
                       └─────────────┘     │
                              │             │
                       ┌─────────────┐      │
                       │ spec-status │──────┘
                       │  (Check)    │
                       └─────────────┘
                              │
                              ▼
                       ┌─────────────┐
                       │   Done!     │
                       └─────────────┘
```

## When to Use Spec Workflows?

### Use when:
- Developing complex new features
- Need clear technical documentation
- Team collaboration, need alignment
- Refactoring large codebase

### Not needed when:
- Simple bug fixes
- Small changes (1-2 lines of code)
- Hotfix production

## Generated Files

When running all 6 commands, the system creates:

```
specs/
└── [feature-name]/
    ├── spec.md              # Main spec (from spec-init)
    ├── requirements.md      # EARS requirements (from spec-requirements)
    ├── design.md            # Technical design (from spec-design)
    ├── tasks.md             # Task breakdown (from spec-tasks)
    └── implementation.md    # Progress tracking (from spec-impl, updated by spec-status)
```
