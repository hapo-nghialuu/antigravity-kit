# /spec-init

Initialize the initial specification file for a new feature.

## Usage

**Claude Code:**
```
/spec-init
```

**Antigravity:**
```
/spec_init
```

## Description

This command creates a `specs/[feature-name]/spec.md` file with a standard structure. This is the first step in Spec-Driven Development.

## Process

1. **Enter feature name**: e.g., "user-authentication", "payment-gateway"
2. **Brief description**: Summary of the feature's purpose
3. **Importance**: Why this feature is needed
4. **Goals**: What needs to be achieved
5. **Scope**: In scope and out of scope
6. **Assumptions**: Assumptions before starting

## Output

The file `specs/[feature-name]/spec.md` is created with:

```markdown
# Feature Spec: [Feature Name]

## 1. Overview
Overall description of the feature...

## 2. Goals
- Goal 1
- Goal 2

## 3. Scope
### In Scope
- ...

### Out of Scope
- ...

## 4. Assumptions
- ...
```

## Example

```
> /spec-init

Feature name: user-authentication
Description: User authentication system with JWT
...

✅ Created: specs/user-authentication/spec.md
```

## Notes

- Feature names should use `kebab-case` (e.g., `user-authentication`)
- This file will be updated in subsequent steps
- Can be manually edited after creation
