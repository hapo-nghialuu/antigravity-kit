## Main path

```text
/hapo:brainstorm         # optional when intent or architecture is unresolved
  -> /hapo:specs         # C1 -> plan.md + flat tasks -> adversarial review -> C2
  -> stop planning
  -> /hapo:develop       # new explicit invocation; one unblocked task at a time
  -> /hapo:test          # smallest adequate real proof
  -> /hapo:code-review   # correctness, security, regressions, contract drift
  -> /hapo:sync          # observed Status and inline Receipt only
  -> C3                  # user completion decision
```

Chat is not the source of truth. New work uses `specs/<feature>/plan.md` and flat `task-NN-*.md` files.

## Contract and execution

`plan.md` records C1 scope, exclusions, acceptance criteria, dependencies, and C2 decisions. Each task owns one outcome, one `Status:`, explicit ownership, dependencies, proof command, and a final inline `## Receipt`.

Develop scouts real entrypoints and callers before mutation. Runtime-facing work is incomplete until it is reachable from the actual route, command, UI mount, worker, service, or API boundary.

Do not silently replace named technologies or runtime choices. A needed scope change returns to the plan and user decision.

## Proof stack

<WorkflowProofStack />

A green command is not enough. Exact acceptance-relevant commands must run; zero tests and `NO_TESTS` do not pass. Review findings block completion until repaired and reverified.

## State ownership

<WorkflowStateRail />

The controller alone updates task Status and canonical Receipt. Sync may reconcile observed file state but cannot invent execution, approval, or completion.

## Alternate routes

| Situation | Route |
|---|---|
| Need an evidence-backed answer | `/hapo:ask` |
| Need scoped codebase discovery | `/hapo:scout` |
| Root cause unknown | `/hapo:debug` |
| Diagnosed bug needs repair | `/hapo:fix` |
| Existing system lacks reliable docs | `/hapo:docs --reconstruct <scope>` |
| Uncertain technical decision | `/hapo:research` |
| Explicit bounded numeric optimization | `/hapo:loop` |

Claude Code uses `/hapo:*`; Codex CLI uses native `$hapo-*` skills. OpenCode commands are historical 0.16-only compatibility notes.
