### CafeKitとは何ですか？

CafeKitは、AIコーディングアシスタントのための仕様駆動（spec-driven）開発ワークフローです。明確な要件定義、段階的な設計、および詳細なタスクの細分化を通じてユーザーとAIをガイドし、機能やアプリケーションを構築するための構造化されたアプローチを提供します。

### どのAIプラットフォームに対応していますか？

現在、CafeKitは以下の環境で動作するように設計されています：
- **Claude Code** (Anthropic)
- **Antigravity** (Google)

### AIにプロンプトを投げて一気にコードを書かせるだけではいけないのですか？

シンプルな変更であれば、それでも問題ありません。しかし複雑な機能の場合、仕様を定めずにコーディングさせると以下のような問題が起きやすくなります：
- エッジケースの考慮漏れ
- 一貫性のない場当たり的なアーキテクチャ設計
- メンテナンス困難なコード（いわゆるスパゲッティコード）
- 終わりの見えない手戻りやデバッグの繰り返し

CafeKitは、コードを書く**前**に必ず「設計・考察」のステップを挟むことで、これらの問題を防ぎます。

### フルスタックアプリの開発にも使えますか？

はい！CafeKitは、小さなフロントエンドコンポーネントの作成から複雑なフルスタックバックエンドシステムの構築まで、開発規模の大小を問わず効果を発揮します。

### EARSフォーマットとは何ですか？なぜ要件定義に使うのですか？

EARS（Easy Approach to Requirements Syntax）は、要件定義における記述の曖昧さを減らすためのルールベースの構文で、特にAIが文脈を正確に理解しやすい形式です。

**基本構造:**
「[条件/トリガー]の**時**、システムは[アクション]する**こと**。」

*例:* 「ユーザーが無効なパスワードを送信した**時**、システムはエラーメッセージを表示する**こと**。」

### `/docs` コマンドによるドキュメント生成はどのような仕組みですか？

`/docs` ワークフロー（Claude Codeの `/docs init` や Antigravityの `/docs-init`）は、**repomix** というツールを使用してプロジェクトのコード全体を、AIが解析しやすい1つのXMLファイルにまとめます。これによりAIアシスタントは、プロジェクトのコンテキスト、設計パターン、既存の構造を素早く理解し、プロジェクトのコーディング基準やガイドラインとなる正確なドキュメントを作成できるようになります。

### repomixは必須ですか？

はい、ドキュメント生成のワークフロー（`/docs` コマンド群）には `repomix` が必要です。グローバル環境にインストールするには、`npm install -g repomix` を実行してください。

### 通常のAIコーディングとの違い

| 機能 | 簡単なAIプロンプト | CafeKit ワークフロー |
|---------|---------------------|---------------------------|
| **企画と計画** | プロンプトのみ。あとはAIが都合よく推測する | 詳細な要件定義と設計を行い、ユーザーが承認する |
| **実行手順** | 一気にすべて、あるいは思いついた順 | タスクを細分化し、1つずつ確実に実行 |
| **品質保証** | 場当たり的なテスト | タスクごとにテストとレビュー（検証）を必須化 |
| **ドキュメント** | 後回し、最悪の場合は一切残らない | 開発プロセス全体が仕様書（Spec）として自動的にドキュメント化される |
| **最適な用途** | 簡単なスクリプト作成、単一ファイルの修正など | 複雑な機能の実装、新規プロジェクト、チーム開発など |

### 次に何をすればいいか分からなくなった時は？

迷ったときは、現在のステータスを確認するために `/spec-status <feature-name>` を実行してください。AIがこれまでの進捗をまとめ、「次は `/code` コマンドを実行してください」のように取るべきアクションを教えてくれます。
