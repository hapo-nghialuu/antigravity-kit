# /spec-tasks

確定した技術設計から、すぐに実装へ移れる粒度のタスクを生成します。

## 使い方

**Claude Code:**
```bash
/spec-tasks user-authentication
/spec-tasks user-authentication -y
```

**Antigravity:**
```bash
/spec-tasks user-authentication
/spec-tasks user-authentication -y
# または
@spec-tasks user-authentication
```

## 説明

コマンドを実行すると、AIは特定の機能を構成する以下の仕様ファイル一式を読み込みます：
- `.specs/[feature-name]/spec.json`
- `.specs/[feature-name]/requirements.md`
- `.specs/[feature-name]/design.md`

解析後、以下のファイルを生成します：
- `.specs/[feature-name]/tasks.md`

生成されるタスクは適切な実行順序が組まれ、どの要件を満たすためのタスクかがマッピングされており、次の `/code` コマンドで即座に実装を開始できる状態になっています。

## タスクリストの構成例

生成される `tasks.md` は、以下のようなフォーマットになります：

```markdown
- [ ] 1. Set up authentication module
- [ ] 1.1 Create auth service interface
  - Define login/logout/session methods
  - _Requirements: 1, 2_

- [ ] 2. Add login endpoint
- [ ] 2.1 Implement POST /api/auth/login
  - Validate input and return token/session
  - _Requirements: 1, 3_
```

## メモ

- 各タスクは明確で粒度が小さく、上から順に実行（シーケンシャル）できるように設計されています
- すべての要件定義が、漏れなくタスクとして網羅されているかを確認してください
- `-y` フラグをつけることで、前段階の要件定義や設計の承認プロセスをスキップし、一気にタスク生成まで自動進行させることができます

## 次のステップ

- [`/code`](/docs/spec/impl) - スプリントプランから未着手のタスクを1つ選んで実装します
- [`/test`](/docs/spec/test) - 実装したコードのテスト（検証）を行います
- [`/review`](/docs/spec/review) - コードの品質チェックと、リグレッションがないかのレビューを行います
