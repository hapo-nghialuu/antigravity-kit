# Spec Workflows

CafeKit Specでは、要件定義から実装、テスト、レビューに至るまで、明確な「仕様駆動（spec-driven）」のコマンドフローに沿って開発を進めます。

## コマンドの呼び出し方

| プラットフォーム | 構文（Syntax） |
|----------|--------|
| **Claude Code** | `/spec-init`, `/spec-requirements`, `/spec-design`, `/spec-tasks`, `/code`, `/test`, `/review`, `/spec-status` |
| **Antigravity** | `/spec-init`, `/spec-requirements`, `/spec-design`, `/spec-tasks`, `/code`, `/test`, `/review`, `/spec-status` |

## 仕様駆動開発（SDD）のプロセス

```text
/spec-init -> /spec-requirements -> /spec-design -> /spec-tasks -> /code -> /test -> /review
                                            |
                                            +--> /spec-status (いつでも現在のフェーズを表示可能)
```

## どんな時にSpecワークフローを使うべきか？

### おすすめのケース:
- 複雑な新機能の開発
- 明確な技術ドキュメントが必要な場合
- チーム開発において、実装前に認識をすり合わせたい場合
- 大規模なコードベースのリファクタリング

### 不要なケース（通常のプロンプトで十分な場合）:
- 簡単なバグ修正
- 1〜2行のちょっとしたコード修正
- 本番環境でのホットフィックス（Hotfix）

## 生成されるファイル群

ワークフローの各フェーズで生成される主要なファイルは以下の通りです：

```
.specs/
└── [feature-name]/
    ├── spec.json            # フェーズ + 承認ステータスメタデータ
    ├── requirements.md      # 要件定義（インプットとアウトプット）
    ├── research.md          # 技術調査やリサーチのメモ（必要な場合のみ）
    ├── design.md            # 技術設計（/spec-designで生成）
    └── tasks.md             # タスクの細分化（/spec-tasksで生成）
```
