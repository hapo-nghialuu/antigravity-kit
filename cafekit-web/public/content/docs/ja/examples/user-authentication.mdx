# User Authentication Example

この例は、JWTベースのユーザー認証を構築するための完全な仕様駆動（spec-driven）ワークフローを示しています。ログイン、サインアップ、パスワードリセット、およびセキュリティのベストプラクティスを網羅しています。

## フェーズ 1: 初期化

```bash
/spec-init user-authentication
```

**初期要件の説明:**
> メールアドレス/パスワードでのログイン、ユーザー登録、パスワードリセット、保護されたルートを持つJWTベースのユーザー認証システム。レート制限と安全なパスワード保存を含めること。

**生成されるspecの構造:**
```
.specs/user-authentication/
├── spec.json
└── requirements.md (テンプレート)
```

## フェーズ 2: 要件定義

`/spec-requirements user-authentication` を実行すると以下が生成されます：

```markdown
# User Authentication - Requirements

## 目的
APIエンドポイントを保護し、パーソナライズされたユーザーエクスペリエンスを可能にするために、JWTトークンによる安全なユーザー認証を実装する。

## ターゲットユーザー
- アプリケーションにアクセスするエンドユーザー
- ユーザーアカウントを管理するシステム管理者

## 機能要件

### FR-1: ユーザー登録
新しいユーザーが有効なメールアドレスとパスワードを提供した**時**、
システムはアカウントを作成し、500ms以内にJWTトークンを返す**こと**。

**受け入れ基準:**
- メールアドレスは一意（ユニーク）でなければならない
- パスワードは8文字以上で、大文字、小文字、数字を含むこと
- 成功時にJWTトークンを返す
- ウェルカムメールを送信する

### FR-2: ユーザーログイン
登録済みユーザーが正しい認証情報を提供した**時**、
システムは認証を行い、24時間有効なJWTトークンを返す**こと**。

**受け入れ基準:**
- メールアドレスが存在するか検証する
- bcryptでパスワードを検証する
- 成功時にJWTトークンを返す
- 失敗時は一般的なエラーを返す（セキュリティのため）

### FR-3: パスワードリセット
ユーザーがパスワードリセットをリクエストした**時**、
システムは1時間有効な安全なリセットリンクを送信する**こと**。

**受け入れ基準:**
- リセットリンクには安全なトークンが含まれる
- トークンは1時間後に期限切れとなる
- 古いパスワードはリセットされるまで有効
- メールは非同期で送信される

### FR-4: 保護されたルート
有効なJWTなしで保護されたエンドポイントにアクセスした**時**、
システムはリクエストを拒否し、ステータス401を返す**こと**。

**受け入れ基準:**
- JWTの署名を検証する
- トークンの有効期限をチェックする
- トークンからユーザーIDを抽出する
- 無効/欠落したトークンに対して401を返す

## 非機能要件

### セキュリティ
- bcrypt（コストファクター12）でハッシュ化されたパスワード
- JWTシークレットは最低256ビット
- レート制限：IPごとに15分間で5回のログイン試行まで
- 本番環境ではHTTPSのみ

### パフォーマンス
- ログイン応答時間 < 500ms
- トークン検証 < 10ms
- 1000人の同時接続ユーザーをサポート

### コンプライアンス
- GDPR準拠（データの削除）
- 認証イベントの監査ログ（Audit logs）
```

## データベーススキーマ

```sql
-- Usersテーブル
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- パスワードリセットトークン
CREATE TABLE password_resets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  token_hash VARCHAR(255) NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- インデックス
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_password_resets_token ON password_resets(token_hash);
```

## セキュリティ対策

1. **パスワードハッシュ化**
   - コストファクター12のbcrypt
   - 平文のパスワードは絶対に保存しない

2. **JWT構成**
   - HS256アルゴリズム
   - 24時間の有効期限
   - 環境変数からの安全なシークレット

3. **レート制限**
   - 15分間に5回の試行
   - IPベースのトラッキング
   - 超過時は429ステータスを返す

4. **入力バリデーション**
   - メールのフォーマット検証
   - パスワードの強度要件
   - SQLインジェクション防止（プレースホルダーを使用したクエリ）

## エラーハンドリング

| シナリオ | ステータス | メッセージ |
|----------|--------|---------|
| 無効なメールフォーマット | 400 | "Invalid email format" |
| 弱いパスワード | 400 | "Password does not meet requirements" |
| 未登録のメール | 400 | "Email already registered" |
| 無効な認証情報 | 401 | "Invalid credentials" |
| トークンなし | 401 | "Authentication required" |
| トークンの期限切れ | 401 | "Token expired" |
| レート制限 | 429 | "Too many attempts" |

## フェーズ 5: 実装

`/code user-authentication` を実行して保留中の次のタスクを実装し、その後 `/test` と `/review` を実行します。

### 重要な実装の詳細

#### パスワードハッシュ化 (`src/lib/password.ts`)

```typescript
import bcrypt from 'bcrypt';

const SALT_ROUNDS = 12;

export async function hashPassword(password: string): Promise<string> {
  return bcrypt.hash(password, SALT_ROUNDS);
}

export async function verifyPassword(
  password: string,
  hash: string
): Promise<boolean> {
  return bcrypt.compare(password, hash);
}
```

#### JWTユーティリティ (`src/lib/jwt.ts`)

```typescript
import jwt from 'jsonwebtoken';

const JWT_SECRET = process.env.JWT_SECRET!;
const JWT_EXPIRES_IN = '24h';

export function signToken(userId: string): string {
  return jwt.sign({ userId }, JWT_SECRET, {
    expiresIn: JWT_EXPIRES_IN,
  });
}

export function verifyToken(token: string): { userId: string } {
  return jwt.verify(token, JWT_SECRET) as { userId: string };
}
```

#### 認証ミドルウェア (`src/middleware/auth.ts`)

```typescript
import { NextRequest, NextResponse } from 'next/server';
import { verifyToken } from '@/lib/jwt';

export function withAuth(handler: Function) {
  return async (req: NextRequest) => {
    const token = req.headers.get('authorization')?.replace('Bearer ', '');

    if (!token) {
      return NextResponse.json(
        { error: 'Authentication required' },
        { status: 401 }
      );
    }

    try {
      const payload = verifyToken(token);
      req.userId = payload.userId;
      return handler(req);
    } catch {
      return NextResponse.json(
        { error: 'Invalid token' },
        { status: 401 }
      );
    }
  };
}
```
