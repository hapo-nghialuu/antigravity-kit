# Documentation Workflows

ドキュメント管理のワークフローは、AIアシスタントがプロジェクトのコード全体をより素早く理解できるように、ドキュメントの生成や更新を自動化するコマンド群です。

## 解決したい課題

AIコーディングアシスタントが効果的にタスクをこなすには、プロジェクトの「コンテキスト（文脈）」が必要です。最新のドキュメントが整っていないと、AIは次のような非効率な動きをしてしまいます：

- プロジェクト全体を毎度スキャンするのに時間を浪費する
- チームのコーディング規約を適当に推測してしまう
- システムアーキテクチャのパターンを誤解する
- アプリ全体で一貫性のない、バラバラなコードを書いてしまう

## 解決策

`/docs` から始まる専用のコマンド群は、[repomix](https://github.com/yamadashy/repomix) を使ってプロジェクトのコードを解析し、標準化されたMarkdownファイルのセットを生成します。生成されたファイルはすべて `.agent/` ディレクトリ（Claude Codeの場合は `.claude/`）や `docs/` に保存されます。

こうして一元管理されたドキュメントファイルが、AIにとっての「信頼できる唯一の情報源（Single Source of Truth）」となるため、不正確な推測を減らし、出力されるコードの品質を安定させます。

## 提供されているコマンド

### [/docs init](/docs/docs-workflow/init)

AI開発の土台となる、プロジェクトの初期ドキュメントを作成します。

**こんな時に使います:**
- 新しいプロジェクトを立ち上げる時
- CafeKitを初めてインストール・セットアップした直後
- 既存のドキュメントが古くなりすぎて使い物にならない時

### [/docs update](/docs/docs-workflow/update)

コードに大きな変更があった際に、既存のドキュメントを最新状態に更新します。

**こんな時に使います:**
- 重要な新機能の実装が完了した直後
- 大規模なリファクタリングを行った後
- アーキテクチャの変更があった時
- AIが古いルールに基づいて、見当違いなコードを書き始めた時

## 事前準備

> [!IMPORTANT]
> これらのドキュメント機能を動かすには、**repomix** をローカル環境にグローバルインストールしておく必要があります。

```bash
npm install -g repomix
# または: pnpm install -g repomix
# または: yarn global add repomix
```

repomixは、AIに読み込ませるのに最適な1つのXMLファイルへとコードベース全体をパッケージングするツールです。 `/docs` コマンドを実行すると、裏側でrepomixが走り、その解析結果をもとにドキュメントが生成されます。

## プラットフォームごとの挙動の違い

### Claude Code (`/docs init`, `/docs update`)

Claude Codeはカスタムの `/docs` コマンド拡張をサポートしているため、以下の形式で実行できます：

```bash
/docs init
/docs update
```

この場合、ドキュメントは `docs/` ディレクトリ配下に複数のファイルとして分割され、それらを束ねるインデックスとして `CLAUDE.md` がプロジェクト直下に作成されます。

#### 1. プロジェクト直下の `CLAUDE.md`
`CLAUDE.md` は、Claude Codeが起動した時に最初に読み込むファイルであり、AIとのやり取りに欠かせない前提知識を提供します。このファイルの中には、プロジェクト独自のルールや、他のドキュメントへのリンク（ポインタ）が記述されます。

#### 2. `docs/` ディレクトリ内の詳細ドキュメント
各ドキュメントはトピックごとに分割されており、AIが検索しやすく、人間がメンテナンスしやすいように設計されています：
- `code-standards.md:` コーディング標準
- `system-architecture.md:` システムアーキテクチャ
- `deployment-guide.md:` デプロイメントガイド
など。

### Antigravity (`/docs-init`, `/docs-update`)

Antigravity プラットフォームでは、ハイフン区切りの以下のコマンドを使用します：

```bash
/docs-init
/docs-update
```

こちらを実行した場合は、情報が `.agent/rules/AGENTS.md` に集約され、 `docs/` ディレクトリへの個別ファイル分割は行われません。

#### `AGENTS.md` の生成
`AGENTS.md` には、システムアーキテクチャ、設計ガイドライン、コーディング規約、チームのルールなど、プロジェクトに関するあらゆる情報が網羅されます。1ファイルのサイズは大きくなりますが、AIにとっては必要な情報が集約された効率的なファイルとなります。
