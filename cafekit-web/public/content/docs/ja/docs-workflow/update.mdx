# /docs update

コードに大きな変更が加わった際、プロジェクトのドキュメントを最新状態に同期させます。

## コマンドの概要

このコマンドは、現在の最新コードと、以前作成された既存ドキュメントの「差分（差）」を検知して更新を行う機能です。（一部のプラットフォームでは `/docs-update` となります）

## 裏側で行われること

コマンドを実行すると、以下の順序で処理が進みます：

1. 前回の状態をリセットし、最新のコードから新しい `repomix-output.xml` を生成します。
2. AIが最新の全コードを読み取り、現在のドキュメント内容と比較します。
3. 追加された新しい設計パターンやルールの変更点を見つけ出します。
4. 該当するドキュメントのファイルを上書き・修正し、情報を最新化します。

## どんな時にドキュメントを更新すべきか

日常的な細かな作業の度に実行する必要はありませんが、以下のようなマイルストーンを越えたタイミングで実行することをお勧めします。

- **アーキテクチャの大規模な変更:** モノリスからマイクロサービスへの分離や、新しいパラダイム（例：React Server Components）を導入した時など。
- **新しいテスト方針の導入:** PlaywrightなどのE2Eテストツールを新しく導入したり、テストの書き方のルールを変えた時など。
- **コードの書き方の大規模な見直し:** プロジェクト全体で「古い書き方」を廃止し、今後のAIには「新しい書き方」を徹底させたい時。
- **AIがピント外れなコードを書き始めた時:** AIが昔の文脈を引きずって古いメソッドや設計を使うようになったら、ドキュメントが古くなっているサインです。

## 実行時のヒント

- アップデート漏れを防ぐため、必ず変更したコードをすべて保存・コミットした状態でこのコマンドを実行してください。
- スプリントの終わりや、区切りとなるメジャーリリースの直後に実行するルーティンにしておくと効果的です。
- ゼロからドキュメントを作り直すわけではなく、変更が必要な差分だけを部分的に修正（パッチ）していくため、コンテキストが失われることはありません。
