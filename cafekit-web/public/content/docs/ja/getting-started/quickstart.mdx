# クイックスタート

この quickstart では現在の CafeKit runtime を使います。

```text
/hapo:specs -> /hapo:develop -> /hapo:test -> /hapo:code-review
```

## 1. CafeKit をインストール

```bash
npx @haposoft/cafekit
```

## 2. Spec を作成

feature を自然言語で説明します。

```bash
/hapo:specs Build a meeting transcript extension with AI summaries
```

CafeKit は次のような spec workspace を生成します。

```text
specs/meet-transcript-mvp/
├── spec.json
├── requirements.md
├── research.md
├── design.md
└── tasks/
    ├── task-R0-01-*.md
    ├── task-R0-02-*.md
    └── ...
```

## 3. Spec を validate

コードを書く前に spec validation を実行します。

```bash
/hapo:specs --validate meet-transcript-mvp
```

ここで CafeKit は次を確認します。

- requirements、design、tasks が整合しているか
- contract が明示的か
- spec が implementation ready か

## 4. 1つの task を実装

最も安全なのは task-by-task execution です。

```bash
/hapo:develop meet-transcript-mvp task-R0-02-auth-setup-dual-mode.md
```

CafeKit は次を行います。

1. task packet を load
2. task boundary を enforce
3. quality gate を実行
4. verification が通った後だけ task state を sync
5. task 単位の docs checkpoint を実行

## 5. Verification を実行

```bash
/hapo:test --full
```

CafeKit は次のような structured verdict を返します。

- `PASS`
- `FAIL`
- `PARTIAL`
- `NO_TESTS`

重要:

- `NO_TESTS` は成功と同義ではありません
- preflight failure は completion を止めるべきです

## 6. Review を実行

```bash
/hapo:code-review --pending
```

実装後に correctness、regression、security を確認するために使います。

## 7. 必要なときに task state を audit

```bash
/hapo:sync audit meet-transcript-mvp
```

次のようなときに使います。

- task files と `spec.json` がずれた
- run が途中で止まった
- 次の unblocked task を確認したい

## 推奨ワークパターン

ほとんどの feature では:

```text
spec -> validate -> develop one task -> test -> review -> next task
```

このパターンなら task state、evidence、docs を揃えたまま進められます。
