# Ví dụ Xác thực Người dùng

Ví dụ này minh họa một quy trình spec-driven hoàn chỉnh để xây dựng xác thực người dùng dựa trên JWT. Nó bao gồm đăng nhập, đăng ký, đặt lại mật khẩu và các thực hành tốt nhất về bảo mật.

## Giai đoạn 1: Khởi tạo

```bash
/spec-init user-authentication
```

**Mô tả ban đầu:**
> Hệ thống xác thực người dùng dựa trên JWT với đăng nhập email/mật khẩu, đăng ký người dùng, đặt lại mật khẩu và các route được bảo vệ. Phải bao gồm giới hạn tốc độ (rate limiting) và lưu trữ mật khẩu an toàn.

**Cấu trúc spec được tạo:**
```
.specs/user-authentication/
├── spec.json
└── requirements.md (template)
```

## Giai đoạn 2: Yêu cầu

Chạy `/spec-requirements user-authentication` tạo ra:

```markdown
# User Authentication - Requirements

## Purpose
Triển khai xác thực người dùng an toàn với JWT token để bảo vệ các API endpoint
và cho phép trải nghiệm người dùng được cá nhân hóa.

## Target Users
- Người dùng cuối truy cập ứng dụng
- Quản trị viên hệ thống quản lý tài khoản người dùng

## Functional Requirements

### FR-1: User Registration
Khi người dùng mới cung cấp email và mật khẩu hợp lệ,
hệ thống sẽ tạo tài khoản và trả về JWT token
trong vòng 500ms.

**Acceptance Criteria:**
- Email phải là duy nhất
- Mật khẩu phải có 8+ ký tự với chữ hoa, chữ thường và số
- Trả về JWT token khi thành công
- Gửi email chào mừng

### FR-2: User Login
Khi người dùng đã đăng ký cung cấp thông tin xác thực chính xác,
hệ thống sẽ xác thực và trả về JWT token
có thời hạn 24 giờ.

**Acceptance Criteria:**
- Xác thực email tồn tại
- Xác minh mật khẩu với bcrypt
- Trả về JWT token khi thành công
- Trả về lỗi chung chung khi thất bại (bảo mật)

### FR-3: Password Reset
Khi người dùng yêu cầu đặt lại mật khẩu,
hệ thống sẽ gửi liên kết đặt lại an toàn có hiệu lực trong 1 giờ.

**Acceptance Criteria:**
- Liên kết đặt lại chứa token an toàn
- Token hết hạn sau 1 giờ
- Mật khẩu cũ vẫn có hiệu lực cho đến khi đặt lại
- Email được gửi bất đồng bộ

### FR-4: Protected Routes
Khi truy cập các endpoint được bảo vệ mà không có JWT hợp lệ,
hệ thống sẽ từ chối yêu cầu với trạng thái 401.

**Acceptance Criteria:**
- Xác thực chữ ký JWT
- Kiểm tra hạn token
- Trích xuất user ID từ token
- Trả về 401 cho token không hợp lệ/thiếu

## Non-Functional Requirements

### Security
- Mật khẩu được băm với bcrypt (cost factor 12)
- JWT secret tối thiểu 256 bits
- Rate limiting: 5 lần thử đăng nhập mỗi 15 phút trên mỗi IP
- HTTPS only trong production

### Performance
- Thời gian phản hồi đăng nhập < 500ms
- Xác thực token < 10ms
- Hỗ trợ 1000 người dùng đồng thời

### Compliance
- Tuân thủ GDPR (xóa dữ liệu)
- Audit logs cho các sự kiện xác thực
```

# User Authentication - Design

## Architecture

## API Design

### POST /api/auth/register

**Request:**
```json
{
  "email": "user@example.com",
  "password": "SecurePass123"
}
```

**Response (201):**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "uuid",
    "email": "user@example.com"
  }
}
```

**Response (400):**
```json
{
  "error": "Email already exists"
}
```

### POST /api/auth/login

**Request:**
```json
{
  "email": "user@example.com",
  "password": "SecurePass123"
}
```

**Response (200):**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "uuid",
    "email": "user@example.com"
  }
}
```

**Response (401):**
```json
{
  "error": "Invalid credentials"
}
```

### POST /api/auth/forgot-password

**Request:**
```json
{
  "email": "user@example.com"
}
```

**Response (200):**
```json
{
  "message": "Reset email sent"
}
```

## Database Schema

```sql
-- Users table
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Password reset tokens
CREATE TABLE password_resets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  token_hash VARCHAR(255) NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_password_resets_token ON password_resets(token_hash);
```

## Security Measures

1. **Password Hashing**
   - bcrypt với cost factor 12
   - Không bao giờ lưu mật khẩu dạng plain text

2. **JWT Configuration**
   - Thuật toán HS256
   - Hết hạn sau 24 giờ
   - Secret an toàn từ biến môi trường

3. **Rate Limiting**
   - 5 lần thử mỗi 15 phút
   - Theo dõi dựa trên IP
   - Trả về trạng thái 429 khi vượt quá

4. **Input Validation**
   - Xác thực định dạng email
   - Yêu cầu độ mạnh mật khẩu
   - Ngăn chặn SQL injection (parameterized queries)

## Error Handling

| Kịch bản | Status | Message |
|----------|--------|---------|
| Định dạng email không hợp lệ | 400 | "Invalid email format" |
| Mật khẩu yếu | 400 | "Password does not meet requirements" |
| Email tồn tại | 400 | "Email already registered" |
| Thông tin xác thực không hợp lệ | 401 | "Invalid credentials" |
| Thiếu token | 401 | "Authentication required" |
| Token hết hạn | 401 | "Token expired" |
| Bị giới hạn tốc độ | 429 | "Too many attempts" |
```

## Giai đoạn 5: Thực hiện

Chạy `/spec-impl user-authentication` hướng dẫn qua từng task.

### Chi tiết thực hiện chính

#### Password Hashing (`src/lib/password.ts`)

```typescript
import bcrypt from 'bcrypt';

const SALT_ROUNDS = 12;

export async function hashPassword(password: string): Promise<string> {
  return bcrypt.hash(password, SALT_ROUNDS);
}

export async function verifyPassword(
  password: string,
  hash: string
): Promise<boolean> {
  return bcrypt.compare(password, hash);
}
```

#### JWT Utility (`src/lib/jwt.ts`)

```typescript
import jwt from 'jsonwebtoken';

const JWT_SECRET = process.env.JWT_SECRET!;
const JWT_EXPIRES_IN = '24h';

export function signToken(userId: string): string {
  return jwt.sign({ userId }, JWT_SECRET, {
    expiresIn: JWT_EXPIRES_IN,
  });
}

export function verifyToken(token: string): { userId: string } {
  return jwt.verify(token, JWT_SECRET) as { userId: string };
}
```

#### Auth Middleware (`src/middleware/auth.ts`)

```typescript
import { NextRequest, NextResponse } from 'next/server';
import { verifyToken } from '@/lib/jwt';

export function withAuth(handler: Function) {
  return async (req: NextRequest) => {
    const token = req.headers.get('authorization')?.replace('Bearer ', '');

    if (!token) {
      return NextResponse.json(
        { error: 'Authentication required' },
        { status: 401 }
      );
    }

    try {
      const payload = verifyToken(token);
      req.userId = payload.userId;
      return handler(req);
    } catch {
      return NextResponse.json(
        { error: 'Invalid token' },
        { status: 401 }
      );
    }
  };
}
```

## Bài học chính

### Những gì đã làm tốt
- Yêu cầu rõ ràng đã ngăn chặn phạm vi bị phình to (scope creep)
- Giai đoạn thiết kế phát hiện sớm các vấn đề bảo mật
- Chia nhỏ task giúp ước lượng chính xác
- Tests phát hiện các vấn đề tích hợp

### Bài học kinh nghiệm
- Giới hạn tốc độ nên được thực hiện sớm (đã chuyển sang TASK 5)
- Dịch vụ email cần mock để testing
- Quy trình xoay vòng (rotation) JWT secret cần tài liệu

### Danh sách kiểm tra bảo mật (Security Checklist)
- ✅ Mật khẩu được băm với bcrypt
- ✅ JWT tokens hết hạn sau 24 giờ
- ✅ Rate limiting khi đăng nhập
- ✅ Input validation trên tất cả endpoint
- ✅ Thông báo lỗi chung chung để bảo mật
- ✅ Bắt buộc HTTPS trong production
