# /docs update

Update documentation to reflect changes in the codebase.

## Usage

**Claude Code:**
```
/docs update
/docs update --focus=src,ui
```

**Antigravity:**
```
/docs_update
/docs_update --focus=src,ui
```

### Optional Flags

| Flag | Description | Example |
|------|-------------|---------|
| `--focus=dir1,dir2` | Only update docs related to specified directories | `--focus=src,components` |
| `--dir=./path` | Target specific directory | `--dir=./my-project` |

## Description

This command scans the current codebase, compares it with existing documentation, and updates the changed parts.

## Difference from `/docs init`

| | `/docs init` | `/docs update` |
|---|---|---|
| **Purpose** | Create docs from scratch | Update existing docs |
| **Overwrite** | All files | Only changed parts |
| **Backup** | Yes | Yes |
| **Time** | Longer | Faster |

## Process

```
1. Scan current codebase
   └── Read all files

2. Compare with old docs
   └── Diff to find changes

3. Update changed sections
   └── Only modify what's needed

4. Backup old docs
   └── Save copy before update

5. Merge and save
   └── Preserve manual edits
```

## Backup

Before updating, the system creates a backup:

```
project-root/
├── docs/
│   ├── codebase-summary.md
│   └── ...
└── docs.backup.20240115_143052/    # Timestamp backup (sibling to docs/)
    ├── codebase-summary.md
    ├── project-overview-pdr.md
    └── ...
```

## Scenarios

### Scenario 1: Adding new features
```
# Before: Codebase has feature A
# After: Add feature B

> /docs update

Update:
- codebase-summary.md (add feature B)
- system-architecture.md (new diagram)
- project-roadmap.md (mark as done)
```

### Scenario 2: Refactoring architecture
```
# Before: Monolith
# After: Microservices

> /docs update

Update:
- system-architecture.md (complete rewrite)
- codebase-summary.md (update structure)
- deployment-guide.md (update deploy process)
```

### Scenario 3: Changing tech stack
```
# Before: Express + MongoDB
# After: Fastify + PostgreSQL

> /docs update

Update:
- codebase-summary.md (new tech stack)
- system-architecture.md (new data layer)
```

## Preserve Manual Edits

`/docs update` tries to preserve manual edits:

```markdown
# In docs/code-standards.md

## Naming Conventions

# [AUTO-GENERATED - Will be updated]
- Functions: camelCase
- Classes: PascalCase

# [MANUAL - Preserve on update]
## Special Cases
- API routes: always use kebab-case
- Database tables: always plural
```

## Best Practices

### When to update
- ✅ After merging large PRs
- ✅ After refactoring
- ✅ End of week/start of week
- ✅ Before handover

### When NOT to update
- ❌ Mid-feature development
- ❌ While debugging
- ❌ When there are many uncommitted changes

## Error Handling

| Scenario | Action |
|----------|--------|
| `docs/` not found | Prompt to run `/docs init` first |
| `repomix` fails | Continue with manual analysis |
| Permission denied | Report path, suggest sudo/fix |
| Conflicts detected | Ask user which version to keep |

## Notes

- Always commit code before `/docs update`
- Review changes after update
- Restore from backup if needed
