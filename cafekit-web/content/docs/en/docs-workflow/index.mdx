# Documentation Workflows

Documentation Workflows provide 2 commands to automate the creation and updating of project documentation—helping AI assistants better understand the codebase.

## Why Documentation Workflows?

### The Problem
When working with AI assistants, each new session:
- AI remembers nothing about the project
- Time is wasted for AI to read and understand the codebase
- Context window is wasted on "catching up"

### The Solution
CafeKit Spec creates 7 standardized documentation files:
1. **codebase-summary.md** - Codebase overview
2. **project-overview-pdr.md** - Product requirements
3. **code-standards.md** - Coding conventions
4. **system-architecture.md** - System architecture
5. **design-guidelines.md** - UI/UX guidelines
6. **deployment-guide.md** - Deployment guide
7. **project-roadmap.md** - Project roadmap

Plus **AGENTS.md** (Antigravity) or **CLAUDE.md** (Claude Code) - Quick reference file for AI.

## Usage Workflow

### First-time project setup
```
> /docs init

Create all documentation files
```

### After major code changes
```
> /docs update

Update documentation to reflect new code
```

## Best Practices

### When to run `/docs init`
- New project setup
- First AI assistant onboarding
- After major structure refactoring

### When to run `/docs update`
- After adding new features
- After architecture changes
- Before handing over to another AI

## File Details

| File | Purpose | When to update |
|------|---------|----------------|
| codebase-summary.md | Tech stack, structure overview | Framework/library changes |
| project-overview-pdr.md | Requirements, goals | Requirements changes |
| code-standards.md | Coding conventions | Conventions changes |
| system-architecture.md | Architecture diagrams | Architecture refactoring |
| design-guidelines.md | UI/UX standards | Design system changes |
| deployment-guide.md | Deploy process | Infrastructure changes |
| project-roadmap.md | Timeline, milestones | New planning |
