# /spec-requirements

Analyze requirements from PRD/Product Context and create requirements in EARS format.

## Usage

**Claude Code:**
```
/spec-requirements
```

**Antigravity:**
```
/spec_requirements
```

## Description

This command reads the `spec.md` file and project context to create `requirements.md` in EARS (Easy Approach to Requirements Syntax) format - a standard for writing clear, testable requirements.

## EARS Format

### Structure

```
[REQ-001] [Type] [Priority]: Requirement description
```

### Type

| Type | Description | Example |
|------|-------------|---------|
| **Functional** | System behavior | "When user clicks login, system will authenticate credentials" |
| **Non-Functional** | Quality requirements | "Response time < 2 seconds" |
| **Constraint** | Technical limitations | "Must use PostgreSQL" |
| **Assumption** | Assumptions | "User has valid email" |

### Priority Levels

| Level | Description |
|-------|-------------|
| **Must** | Required |
| **Should** | Should have, but flexible |
| **Could** | Can have if time permits |

## Output

File `specs/[feature-name]/requirements.md`:

```markdown
# Requirements: [Feature Name]

## Functional Requirements

[REQ-001] [Functional] [Must]: When user enters correct username/password,
system will return JWT token

[REQ-002] [Functional] [Must]: When user enters wrong password 5 times,
system will lock account for 30 minutes

## Non-Functional Requirements

[REQ-010] [Non-Functional] [Must]: Authentication API must respond
within 500ms

## Constraints

[REQ-020] [Constraint] [Must]: Must use JWT with HS256 algorithm
```

## Process

1. AI reads `spec.md` and project context
2. AI analyzes and creates EARS requirements
3. User reviews and modifies
4. Saves to `requirements.md`

## Notes

- Requirements must be **measurable**
- Each REQ should have a single responsibility
- Priority helps team identify the critical path
