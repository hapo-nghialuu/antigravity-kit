# /spec-design

Create technical design document based on analyzed requirements.

## Usage

**Claude Code:**
```
/spec-design
```

**Antigravity:**
```
/spec_design
```

## Description

This command reads `spec.md` and `requirements.md` to create `design.md` - a document describing detailed technical implementation approach.

## Design Document Content

### 1. Technical Architecture

Describe overall architecture:
- Layer/component structure
- Data flow
- Integration points

### 2. Data Model

```
┌─────────────┐       ┌─────────────┐
│    User     │───────│   Session   │
├─────────────┤       ├─────────────┤
│ id          │       │ id          │
│ email       │       │ user_id     │
│ password    │       │ token       │
│ created_at  │       │ expires_at  │
└─────────────┘       └─────────────┘
```

### 3. API Design

| Method | Endpoint | Description | Request | Response |
|--------|----------|-------------|---------|----------|
| POST | /api/auth/login | Login | `{email, password}` | `{token}` |
| POST | /api/auth/logout | Logout | `{token}` | `{success}` |

### 4. Error Handling

| Error Code | HTTP Status | Description |
|------------|-------------|-------------|
| AUTH001 | 401 | Invalid credentials |
| AUTH002 | 403 | Account locked |

### 5. Security Considerations

- JWT secret rotation
- Rate limiting
- Password hashing (bcrypt)

## Output

File `specs/[feature-name]/design.md`:

```markdown
# Technical Design: [Feature Name]

## 1. Architecture
...

## 2. Data Model
...

## 3. API Design
...

## 4. Implementation Notes
...

## 5. Testing Strategy
...
```
