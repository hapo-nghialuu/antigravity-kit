# /spec-requirements

Phân tích yêu cầu từ PRD/Product Context và tạo requirements theo định dạng EARS.

## Sử dụng

**Claude Code:**
```
/spec-requirements
```

**Antigravity:**
```
/spec_requirements
```

## Mô tả

Lệnh này đọc file `spec.md` và context từ project để tạo `requirements.md` với định dạng EARS (Easy Approach to Requirements Syntax) - một chuẩn viết requirements rõ ràng, có thể kiểm tra được.

## Định dạng EARS

### Cấu trúc

```
[REQ-001] [Loại] [Priority]: Mô tả yêu cầu
```

### Loại (Type)

| Loại | Mô tả | Ví dụ |
|------|-------|-------|
| **Functional** | Hành vi hệ thống | "Khi ngườì dùng nhấn đăng nhập, hệ thống sẽ xác thực thông tin" |
| **Non-Functional** | Yêu cầu chất lượng | "Thờì gian phản hồi < 2 giây" |
| **Constraint** | Giới hạn kỹ thuật | "Phải sử dụng PostgreSQL" |
| **Assumption** | Giả định | "Ngườì dùng có email hợp lệ" |

### Mức độ ưu tiên (Priority)

| Mức | Mô tả |
|-----|-------|
| **Must** | Bắt buộc có |
| **Should** | Nên có, nhưng có thể linh hoạt |
| **Could** | Có thể có nếu thờì gian cho phép |

## Output

File `specs/[feature-name]/requirements.md`:

```markdown
# Requirements: [Feature Name]

## Functional Requirements

[REQ-001] [Functional] [Must]: Khi ngườì dùng nhập đúng username/password,
hệ thống sẽ trả về JWT token

[REQ-002] [Functional] [Must]: Khi ngườì dùng nhập sai mật khẩu 5 lần,
hệ thống sẽ khóa tài khoản trong 30 phút

## Non-Functional Requirements

[REQ-010] [Non-Functional] [Must]: API authentication phải phản hồi
trong vòng 500ms

## Constraints

[REQ-020] [Constraint] [Must]: Phải sử dụng JWT với HS256 algorithm
```

## Quy trình

1. AI đọc `spec.md` và project context
2. Phân tích và tạo requirements EARS
3. Ngườì dùng review và sửa đổi
4. Lưu vào `requirements.md`

## Lưu ý

- Requirements phải **measurable** (có thể đo lường)
- Mỗi REQ nên có 1 responsibility duy nhất
- Priority giúp team biết đâu là critical path
