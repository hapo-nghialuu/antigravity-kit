## Quy trình SDD

```text
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  spec-init  │───▶│ requirements│───▶│   design    │
│  (Khởi tạo) │    │  (Yêu cầu)  │    │ (Thiết kế)  │
└─────────────┘    └─────────────┘    └─────────────┘
                                              │
                       ┌─────────────┐       │
                       │  spec-impl  │◀──────┘
                       │(Triển khai) │◀────┐
                       └─────────────┘     │
                              │             │
                       ┌─────────────┐      │
                       │ spec-status │──────┘
                       │(Kiểm tra)   │
                       └─────────────┘
                              │
                              ▼
                       ┌─────────────┐
                       │   Done!     │
                       └─────────────┘
```

## Khi nào dùng Spec Workflows?

### Dùng khi:
- Phát triển tính năng mới phức tạp
- Cần tài liệu kỹ thuật rõ ràng
- Làm việc nhóm, cần alignment
- Refactoring codebase lớn

### Không cần khi:
- Fix bug đơn giản
- Thay đổi nhỏ (1-2 dòng code)
- Hotfix production

## Files Được Tạo

Khi chạy đầy đủ 6 lệnh, hệ thống sẽ tạo:

```
specs/
└── [feature-name]/
    ├── spec.md              # Spec chính (từ spec-init)
    ├── requirements.md      # Requirements EARS (từ spec-requirements)
    ├── design.md            # Technical design (từ spec-design)
    ├── tasks.md             # Task breakdown (từ spec-tasks)
    └── implementation.md    # Progress tracking (từ spec-impl, cập nhật bởi spec-status)
```
