# CafeKit Spec Documentation

Welcome to CafeKit Spec - a structured spec-driven development workflow for Claude Code.

## What is CafeKit Spec?

CafeKit Spec extends Claude Code with 6 powerful workflow commands that guide you through building complex features:

1. **Initialize** - Create spec workspace
2. **Requirements** - Capture what you need
3. **Design** - Define architecture
4. **Tasks** - Break down implementation
5. **Implement** - Build with AI guidance
6. **Status** - Track progress

Instead of ad-hoc prompts, CafeKit Spec gives you a repeatable process for turning ideas into production code.

## Why Spec-Driven Development?

Traditional AI coding often leads to:
- Incomplete requirements causing rework
- Missing edge cases discovered late
- Lost context between sessions
- Inconsistent implementation

**CafeKit Spec solves this** by creating a structured workflow.

**Result:** Faster development, fewer bugs, better documentation.

## Getting Started

### 1. Install CafeKit Spec

```bash
npx @haposoft/cafekit-spec
```

Installs 6 spec workflow commands to your Claude Code.

### 2. Create Your First Spec

Follow our interactive quickstart:

```bash
/spec-init my-first-feature
/spec-requirements my-first-feature
```

The AI guides you through defining requirements, designing architecture, and breaking down tasks.

### 3. Implement with AI Guidance

```bash
/spec-impl my-first-feature
```

The AI reads your spec and helps you build task-by-task, with verification at each step.

## Core Concepts

### Specs

A **spec** is a structured workspace for one feature. It contains:

- `requirements.md` - What you're building and why
- `design.md` - Technical architecture and contracts
- `tasks/sprint-1.md` - Prioritized task breakdown
- `status.md` - Implementation progress

Specs live in `.specs/` and are committed to Git for team collaboration.

### Workflow Commands

CafeKit Spec adds 6 slash commands to Claude Code:

| Command | Purpose |
|---------|---------|
| `/spec-init` | Create spec workspace |
| `/spec-requirements` | Gather requirements via Socratic Q&A |
| `/spec-design` | Generate technical design document |
| `/spec-tasks` | Break down into implementation tasks |
| `/spec-impl` | Implement tasks with AI guidance |
| `/spec-status` | View progress and blockers |

## Use Cases

### Perfect for:

- **Complex features** - Authentication, payments, admin dashboards
- **New projects** - Architecture decisions need documentation
- **Team collaboration** - Specs provide shared context
- **Long-running work** - Track progress across multiple sessions

### Not needed for:

- Simple bug fixes (&lt;30 min)
- Copy changes or typo fixes
- Minor CSS tweaks
- Trivial refactors
