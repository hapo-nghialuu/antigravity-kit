## Features Locked for v0.2.0

### Priority P0: Must Have (4.5 hours)

#### 1. CLI Platform Override Flag (2 hours)

**User Problem:**
- Hybrid projects (both .agent/ and .claude/) cause confusion
- Platform auto-detection doesn't work for edge cases
- Users can't force installation to specific platform

**Solution:**
\`\`\`bash
npx @haposoft/cafekit-spec --platform=antigravity
npx @haposoft/cafekit-spec --platform=claude
npx @haposoft/cafekit-spec --force  # Overwrite existing files
\`\`\`

**Implementation:**
- Add yargs/commander for CLI argument parsing
- Parse --platform flag and validate (antigravity|claude)
- Override auto-detection logic when flag present
- Add --force flag to skip "file exists" checks

**Verification:**
- Test with hybrid project (both folders exist)
- Test --platform=antigravity → Files go to .agent/
- Test --platform=claude → Files go to .claude/
- Test --force → Overwrites existing files

**User Value:**
- Control over installation target
- Solves edge case #9 from v0.1.0

#### 2. Verbose/Debug Mode (1.5 hours)

**User Problem:**
- Installation fails silently
- Users don't know what went wrong
- Troubleshooting is difficult

**Solution:**
\`\`\`bash
npx @haposoft/cafekit-spec --verbose
\`\`\`

**Output Example:**
\`\`\`
🔍 Debug: Checking for .agent/workflows/
🔍 Debug: Found .agent/workflows/ → Antigravity detected
🔍 Debug: Source dir: /path/to/node_modules/@haposoft/cafekit-spec/src/antigravity/workflows
🔍 Debug: Target dir: /path/to/project/.agent/workflows
🔍 Debug: Copying spec-init.md...
✅ Success: spec-init.md copied
🔍 Debug: Copying spec-requirements.md...
⏭️  Skip: spec-requirements.md already exists
...
\`\`\`

**Implementation:**
- Add verbose flag to CLI parser
- Add debug logging throughout install.js
- Use chalk library for colored output
- Show each step: detection, copying, skipping

**Verification:**
- Run with --verbose → See detailed output
- Run without → See normal output
- Test error scenarios with --verbose

**User Value:**
- Easy troubleshooting
- Visibility into what CLI is doing
- Better error identification

#### 3. Dry-Run Mode (1 hour)

**User Problem:**
- Users want to preview before committing
- Fear of overwriting existing files
- Unclear what will happen

**Solution:**
\`\`\`bash
npx @haposoft/cafekit-spec --dry-run
\`\`\`

**Output Example:**
\`\`\`
🔍 Dry Run Mode (no files will be copied)

Platform detected: claude
Target directory: .claude/commands/

Files that would be copied:
✅ spec-init.md
✅ spec-requirements.md
✅ spec-design.md
✅ spec-tasks.md
✅ spec-impl.md
✅ spec-status.md

Total: 6 files (0 would be skipped)

Run without --dry-run to install.
\`\`\`

**Implementation:**
- Add --dry-run flag
- Perform all checks without writing files
- Show preview of what would happen
- Exit after preview

**Verification:**
- Run with --dry-run → No files created
- Output shows correct target directory
- Run again without --dry-run → Files created

**User Value:**
- Safety and confidence
- Preview before commit
- No surprises

- Users don't know when new version is available
- No easy way to see what changed

**Solution:**

Changelog:
- Added --platform flag
- Added --verbose mode
- Added --dry-run mode
- Added update command
- Added uninstall command
- Added config file support

✅ Backed up to .specs/backup/2026-02-02/

🔄 Updating...
✅ Updated spec-init.md
✅ Updated spec-requirements.md
...

✅ Update complete! v0.1.0 → v0.2.0

**Implementation:**
- Check package.json version (locally installed)
- Fetch latest version from npm registry API
- Compare versions (semver)
- Backup existing files before overwrite
- Show diff/changelog
- Copy new files
- Confirm success

**Verification:**
- Mock old version → update → New files copied
- Test backup creation
- Test version comparison
- Test when already latest version

**User Value:**
- Easy updates without manual work
- No risk of losing custom edits (backup)
- Visibility into what changed

#### 6. Config File Support (2.5 hours)

**User Problem:**
- Passing flags every time is tedious
- Different projects need different settings
- No way to persist preferences

**Solution:**

Create \`.cafekit.yml\` in project root:
\`\`\`yaml
platform: claude          # Force platform (antigravity|claude)
auto-update: false        # Auto-update on run (default: false)
verbose: false            # Enable verbose mode (default: false)
backup-before-update: true # Backup before updates (default: true)
\`\`\`

**Behavior:**
\`\`\`bash
# Config file exists → Use config
npx @haposoft/cafekit-spec

# CLI flags override config
npx @haposoft/cafekit-spec --platform=antigravity  # Overrides config
\`\`\`

**Implementation:**
- Check for .cafekit.yml in project root
- Parse YAML (use js-yaml library)
- Merge config with CLI flags (flags take precedence)
- Validate config values
- Apply config to installation logic

**Verification:**
- Create .cafekit.yml with platform: claude → Installs to .claude/
- Override with --platform=antigravity → Installs to .agent/
- Test invalid config → Show error

**User Value:**
- Save preferences per-project
- No need to remember flags
- Team can share config (commit .cafekit.yml)

## Risk Assessment

### Technical Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Breaking changes (v0.2 breaks v0.1 users) | Low | High | Maintain backward compatibility, test both |
| CLI parsing library bugs | Low | Medium | Use well-tested library (yargs), fallback |
| Config file parsing errors | Medium | Low | Validate YAML, clear error messages |
| Update command conflicts | Medium | Medium | Backup before update, allow rollback |

### Process Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Dev overrun (>11h) | Medium | Medium | 30 min buffer each day, cut P1 if needed |
| Beta testers don't test (Day 19) | Medium | Low | Send reminders, offer 1-on-1 help |
| Scope creep (users request more) | High | Medium | Stick to P0+P1, defer P2 clearly |
